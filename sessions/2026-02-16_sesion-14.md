## Errores Encontrados y Fixes (en orden cronologico)

### Fix 1: DB_PATH vacio crasheaba el servidor
**Error:** Cuando `${user_config.database_path}` no se configura, `RESEARCH_MATCH_DB=""` (string vacio). `os.environ.get("RESEARCH_MATCH_DB", "research_match.db")` retorna `""` (no el default), causando `init_database("")` → crash.

**Archivo:** `src/research_match_server.py:124`
**Cambio:**
```python
# Antes:
DB_PATH = os.environ.get("RESEARCH_MATCH_DB", "research_match.db")
# Despues:
DB_PATH = os.environ.get("RESEARCH_MATCH_DB") or "research_match.db"
```

---

### Fix 2: Python 3.13 roto — uv elegia version inexistente
**Error:** `uv run` intentaba usar `cpython-3.13.12-windows-x86_64-none` que no estaba instalado (solo marcado como `<download available>`). Fallaba con:
```
Failed to create temporary virtualenv
Could not find a suitable Python executable
```

**Solucion:** Crear `.python-version` en la raiz del proyecto con contenido `3.12`, incluido en el DXT. Esto fuerza a `uv` a usar Python 3.12 que si esta instalado.

**Archivo nuevo:** `.python-version`
**Archivo modificado:** `build_alpha.sh` (agregar .python-version a los archivos del DXT/ZIP)

---

### Fix 3: Hatch no encontraba el modulo (wheel build failure)
**Error:** `uv run research-match` fallaba con:
```
ValueError: Unable to determine which files to ship inside the wheel
The most likely cause is that there is no directory that matches the name of your project (research_match)
```

Hatch buscaba un directorio `research_match/` pero tenemos un archivo suelto `src/research_match_server.py`.

**Archivo:** `pyproject.toml`
**Cambio:**
```toml
# Antes:
[tool.hatch.build.targets.wheel]
sources = ["src"]

# Despues:
[tool.hatch.build.targets.wheel]
packages = ["src/research_match_server.py"]
```

---

### Fix 4: typing_extensions faltante (dependencia transitiva)
**Error:** `anyio` (usado por `mcp`) importa `typing_extensions` pero no se instalaba automaticamente:
```
ModuleNotFoundError: No module named 'typing_extensions'
```

**Archivo:** `pyproject.toml`
**Cambio:** Agregar `"typing_extensions>=4.0"` a la lista de dependencies.

---

### Fix 5: app_lifespan() sin argumento (incompatibilidad mcp>=1.0)
**Error:** La nueva version de `mcp` pasa el objeto `app` al lifespan, pero nuestra funcion no lo aceptaba:
```
TypeError: app_lifespan() takes 0 positional arguments but 1 was given
```

**Archivo:** `src/research_match_server.py:1691`
**Cambio:**
```python
# Antes:
async def app_lifespan():
# Despues:
async def app_lifespan(app):
```

---

### Fix 6: Tipo de servidor incorrecto en manifest (sandbox/virtiofs failure)
**Error:** Con `server.type: "python"`, Claude Desktop intentaba ejecutar en sandbox VM con virtiofs, que fallaba:
```
sandbox-helper: host share not mounted at /mnt/.virtiofs-root/shared: not a mount point
```

**Solucion:** Cambiar a `server.type: "uv"` (experimental, manifest v0.4+). Con este tipo, Claude Desktop gestiona la ejecucion directamente sin mcp_config manual.

**Archivo:** `manifest.json`
**Cambio:**
```json
// Antes:
{
  "manifest_version": "0.3",
  "server": {
    "type": "python",
    "entry_point": "./src/research_match_server.py",
    "mcp_config": {
      "command": "uv",
      "args": ["--directory", "${__dirname}", "run", "research-match"],
      "env": { "RESEARCH_MATCH_DB": "${user_config.database_path}" }
    }
  }
}

// Despues:
{
  "manifest_version": "0.4",
  "server": {
    "type": "uv",
    "entry_point": "./src/research_match_server.py"
  }
}
```
