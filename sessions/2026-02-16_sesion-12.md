## Objetivo

Crear una simulación completa de 2 usuarios (Alice y Bob) que ejercite el flujo completo del plugin: registro → submit → match → colaboración → reveal → file sharing → ratings → audit. Validar que todos los tools funcionan correctamente en secuencia con datos realistas.

## Trabajo Realizado

### 1. Script de Simulación (`test_simulation_2users.py`)

Script Python async que:
- Crea DB fresca con `init_database()`
- Instancia engines reales (EmbeddingEngine con CUDA, OriginalityEvaluator, MatchingEngine, ReputationEngine)
- Usa `MagicMock` para crear contexto MCP (`ctx.request_context.lifespan_state`)
- Implementa `switch_user()` hack: manipula `created_at` para cambiar `_get_current_user()`
- Ejecuta todos los tools via `await research_match_tool(Input(...), ctx=CTX)`

## Bugs Encontrados y Corregidos

| Bug | Campo Correcto | Campo Incorrecto |
|-----|----------------|-------------------|
| SolidityLevels field | `demos` | `demonstrations` |
| NeedsCreateInput fields | `type`, `area`, `description` | `ticket_type`, `body` |
| NeedsResolveInput | requiere `resolution` (resolved/wont_fix) | solo `resolution_note` |
| reveal_consents column | `approver_id` | `responder_id` |
| RateUserInput field | `rated_user_id`, ratings 1-5 | `target_user_id`, ratings 1-10 |
| respond_request response | `result["team"]["team_id"]` | `result["team_id"]` |
| Table name | `research_commits` | `commits` |

Estos bugs son solo en el script de simulación, no en el servidor. Revelan que los nombres de campos en Pydantic models no siempre son intuitivos — oportunidad de mejora de documentación.

## Observaciones

1. **Semáforo YELLOW correcto** — Alice gana 6.2% de Bob, Bob gana 23.1% de Alice. El matching detecta correctamente que la complementariedad es moderada (distributed systems + blockchain reputation).

2. **`_get_current_user` hack funciona** — Manipular `created_at` para simular switch de usuario es suficiente para testing, pero no es producción. En producción real cada usuario tiene su propia conexión MCP.

3. **find_collaborators almacena YELLOW** — A diferencia de lo que se pensaba en sesiones anteriores, `find_collaborators` SÍ almacena matches YELLOW en la tabla `matches`. El manual insert no fue necesario.

4. **Oportunidad futura** — Los nombres de campos en Pydantic models (`rated_user_id` vs `target_user_id`, `demos` vs `demonstrations`) podrían beneficiarse de aliases o mejor documentación inline.
