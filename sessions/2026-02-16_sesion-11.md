## Objetivo

Implementar una **proforma universal** que cualquier IA pueda llenar leyendo un repositorio, para que el resultado sea consistente y directamente submittable a Research Match. El problema principal: `analyze_repo.py` auto-extrae bien datos deterministas (languages, LOC, deps) pero produce datos pobres para campos narrativos que alimentan el scoring (theoretical_framework, hypothesis, problem, adhoc_summary, cherry_picking).

**Decisiones del usuario:**
- 100% AI-fillable (la IA lee el repo, llena todo, humano solo revisa)
- Universal (software, papers, datasets, frameworks teóricos)
- Prompt template estándar (mismo para todos, consistencia máxima)

### 4. MCP Tool: `research_match_prepare_commit`

**Descripción:** ~700 chars, STEP 1.5 en el flujo.
**Annotations:** readOnlyHint=False, idempotentHint=True, openWorldHint=True.

**3 modos:**

#### Mode `extract`:
1. Resolver source (local path o clone temporal)
2. Ejecutar analyze_repo functions (git, readme, file_tree, dependencies)
3. Detectar project_type, extraer demo_types y code_languages (machine)
4. Seleccionar key files y construir prompt
5. Retornar: proforma_ready + machine_data + prompt_template + instructions

#### Mode `validate`:
1. Parsear narrative_json → ProformaNarrativeData
2. Correr _validate_narrative (errores vs warnings)
3. Retornar: valid/has_errors + errors + warnings + preview

#### Mode `submit`:
1. Validate (mismo que arriba)
2. Si errores → retornar, no submit
3. Mapear proforma → commit_data (machine fields override)
4. evaluate_commit via OriginalityEvaluator
5. INSERT en research_commits
6. Retornar: submitted + scores + solidity impact

### 5. Diseño: Proforma en 2 partes

| Parte | Source | Campos |
|-------|--------|--------|
| Machine (determinista) | analyze_repo.py | code_languages, demo_types, total_files, LOC, commits |
| Narrative (AI) | Prompt template | domain, problem, hypothesis, framework, summaries, solidity |

**Regla clave:** Machine fields NO son overrideables — code_languages y demo_types vienen de extracción factual. La IA NO los toca.

### 6. Prompt Template Universal

- ~2000 chars de instrucciones
- Recibe project_type_hint y adapta guía (SOFTWARE/PAPER/DATASET/THEORETICAL)
- Inyecta machine data como JSON compacto
- Inyecta contenido de key files
- 10 campos con instrucciones detalladas por campo
- Explica impacto de solidity en scoring (multipliers) para incentivar honestidad
- Output: JSON puro sin markdown code blocks

### 7. Validación narrativa

**Errores (bloquean submit):**
- domain = project_name → "no es un campo científico"
- problem < 20 chars → "demasiado corto"
- solidity values no válidos

**Warnings (informativos):**
- hypothesis vacía
- theoretical_framework vacío
- demonstrations_summary < 20 palabras
- adhoc_summary vacío
- demos_solidity='proven' sin test files
- overall_solidity='proven' con < 10 commits
- overall_solidity='cherry_picked' con adhoc_summary largo

## Decisiones de diseño

1. **Proforma en 2 partes** — machine (determinista) + narrative (AI) evita que la IA invente datos factuales
2. **Prompt template estándar** — mismo para todos, consistencia garantizada entre proyectos
3. **3 modos en 1 tool** — extract/validate/submit evita crear 3 tools separados
4. **Project type hint** — adapta el prompt sin cambiar schema
5. **Validation con errores vs warnings** — errores bloquean, warnings informan
6. **Machine fields no overrideables** — code_languages y demo_types son factuales
7. **Solidity con reasoning** — obliga a justificar el nivel, incentiva honestidad
8. **Reusa infraestructura existente** — _import_analyze_repo, _deep_search_clone, OriginalityEvaluator
