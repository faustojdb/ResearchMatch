# Sesion 09 — NEED-05: Audit Log Viewer + Re-sharing Control (MAD)

**Fecha:** 2026-02-16
**Version:** 2.5.0-file-sharing → 2.5.1-audit-mad
**Duracion:** ~20 min

## Objetivo

Implementar dos features en un solo NEED:
1. **Part A:** Tool read-only para visualizar el audit trail (`research_match_audit_log`)
2. **Part B:** Deteccion de re-sharing en `share_file` con penalizacion MAD (Mutual Assured Destruction)

## Contexto

- `audit_log` tenia 11 call sites pero ningun tool para leerlo
- `violation_detected` existia como action valida en el CHECK constraint pero nunca se usaba
- El manifesto definia un mecanismo MAD para prevenir re-sharing de contenido ajeno

## Cambios realizados

### Part A — Audit Log Viewer

| Componente | Detalle |

### Part B — Re-sharing Detection (MAD v1)

| Componente | Detalle |
|------------|---------|

| Hook en `share_file` | Despues del L3 gate, antes del file limit check. Detecta → tankea honesty → audit log → bloquea share |

## Decisiones de diseno

1. **Hash-based detection only** — sin hash no hay deteccion; incentiva proveer hashes
2. **Penalty v1: honesty tankeada** — `running_honesty = 1.0` y `avg_honesty = 1.0`, no bloquea usuario completamente
3. **Cross-team hash check** — busca en TODOS los teams, no solo el actual (re-sharing entre teams es la violacion principal)
4. **Same user + same hash = valido** — compartir tu propio archivo en otro team esta permitido
5. **Audit viewer no escribe entries** — a diferencia de `shared_files` que logea `file_accessed`
6. **action_filter libre** — si no matchea ningun tipo, retorna 0 entries sin error
