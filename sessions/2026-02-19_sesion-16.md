# Session 16 — Cloud Run Deploy (2026-02-19)

## Objective
Deploy Research Match v3.0.0 to Cloud Run with Firestore backend.

## What Was Done

### 1. Fixed Dockerfile Build Failures
**Problem 1:** `OSError: Readme file does not exist: README.md`
- Hatchling build backend requires README.md (referenced in pyproject.toml)
- **Fix:** Added `COPY pyproject.toml README.md ./` in both builder and runtime stages

**Problem 2:** PyTorch downloading CUDA packages (~3GB: nvidia-cudnn, nvidia-cublas, torch-cuda)
- Cloud Run is CPU-only, CUDA is wasted space and bandwidth
- **Fix:** Pre-install CPU-only PyTorch before main dependencies:
  ```dockerfile
  RUN uv pip install --system --no-cache torch --index-url https://download.pytorch.org/whl/cpu
  RUN uv pip install --system --no-cache .
  ```
- Result: 87 packages, ~200MB torch vs ~3GB with CUDA, build in 3 minutes

### 2. Fixed Cloud Run Startup — Host Binding
**Problem:** Container failed health check with `DEADLINE_EXCEEDED`
- Logs showed: `Uvicorn running on http://127.0.0.1:8080` — localhost only
- Cloud Run health checks come from external, need `0.0.0.0`
- **Fix:** Added `mcp.settings.host = "0.0.0.0"` for Cloud Run mode

### 3. Fixed MCP DNS Rebinding Protection
**Problem:** `Invalid Host header` (HTTP 421) on all MCP requests
- MCP SDK v1.26 has `TransportSecuritySettings` that auto-enables DNS rebinding protection for localhost
- Since `FastMCP.__init__` runs at import time with default host (`127.0.0.1`), protection activates before we change host
- Cloud Run's Host header (`research-match-77626397872.us-central1.run.app`) is not in allowed list
- **Fix:** Explicitly disable DNS rebinding protection for Cloud Run:
  ```python
  from mcp.server.transport_security import TransportSecuritySettings
  mcp.settings.transport_security = TransportSecuritySettings(
      enable_dns_rebinding_protection=False,
  )
  ```

### 4. Fixed Secret Manager Permissions
- Cloud Run service account (`77626397872-compute@developer.gserviceaccount.com`) needed `roles/secretmanager.secretAccessor`
- Also created missing `ALGOLIA_INDEX_NAME` secret

### 5. E2E Verification on Cloud Run
All tests passed on production Cloud Run:
- `GET /health` → `{"status":"ok","version":"3.0.0","database":"firestore","backend":"firestore"}`
- `register` → Created and cleaned test user
- `cold_search` → GitHub search working
- MCP session management (initialize + tool calls) working

## Key Learnings
1. **CPU-only PyTorch**: Use `--index-url https://download.pytorch.org/whl/cpu` to avoid 3GB CUDA downloads
2. **Cloud Run host binding**: Must set `0.0.0.0`, default `127.0.0.1` fails health checks
3. **MCP DNS rebinding**: `TransportSecuritySettings` auto-activates for localhost hosts at init time, must explicitly disable for cloud deployments
4. **Secret Manager IAM**: Cloud Run compute service account needs explicit `secretAccessor` role
5. **MCP Accept header**: Client must send `Accept: application/json, text/event-stream`
