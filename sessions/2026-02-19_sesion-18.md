Total de tools: 26.

## Trabajo realizado

### 1. Nuevo modulo: `src/github_client.py`
- Clase `GitHubAppClient` siguiendo patron de `src/algolia_client.py`
- JWT RS256 auth con 10-min expiry (spec de GitHub)
- Cache de installation tokens (55 min, tokens duran 60 min)
- Metodos: `find_installation_for_user()`, `get_installation_repos()`, `add_collaborator()`, `remove_collaborator()`
- `is_configured` property para graceful degradation si no hay credenciales
- Env vars: `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY` (inline PEM o path), `GITHUB_APP_SLUG`
- Dependencias: `httpx` (ya instalado) + `PyJWT` + `cryptography` (ya en venv)

### 2. DataStore — 5 metodos abstractos
- `get_github_connection(user_id)` → connection info o None
- `upsert_github_connection(user_id, github_username, installation_id, authorized_repos)`
- `delete_github_connection(user_id)`
- `get_github_connections_for_team(team_id)` → lista de conexiones de miembros
- `update_github_authorized_repos(user_id, authorized_repos)`

### 3. Firestore implementation
- GitHub connection embebida en documento de usuario: `users/{user_id}.github_connection`
- Schema: `{github_username, installation_id, authorized_repos[], connected_at}`
- Usa `document.update({"github_connection": {...}})` para set, `None` para delete
- `get_github_connections_for_team()`: obtiene member IDs y lee cada usuario

### 4. SQLite schema
- Nueva tabla `github_connections` (user_id PK, github_username, installation_id, authorized_repos JSON, connected_at)
- Audit log CHECK constraint expandido con 4 nuevas acciones: `github_connected`, `github_disconnected`, `repo_access_granted`, `repo_access_revoked`

### 5. Pydantic models
- `ConnectGitHubInput(github_username)` — regex validation de formato GitHub username
- `DisconnectGitHubInput(confirm)` — requiere `confirm=true` explicito

### 6. Lifespan + helpers
- `GitHubAppClient()` inicializado en `app_lifespan`, agregado al yield dict, cerrado en cleanup
- `_get_github_client(ctx)` — retorna client si configurado, None si no
- `_grant_bilateral_repo_access(db_or_ds, github_client, team_id, triggering_user_id)` — agrega collaborator pull en repos de ambos miembros (max 5 repos)
- `_revoke_bilateral_repo_access(db_or_ds, github_client, team_id, triggering_user_id)` — remueve collaborator access en ambas direcciones

### 7. MCP Tool #25: `connect_github`
- Flujo en 2 fases: (1) username → si App no instalada, retorna install URL; (2) usuario instala, llama de nuevo → server verifica via API, almacena conexion
- Si ya conectado, refresca lista de repos
- Auto-grant: si hay contratos confirmados, otorga acceso automaticamente al conectar

### 8. MCP Tool #26: `disconnect_github`
- Requiere `confirm=true`
- Revoca acceso en todos los repos de todos los teams del usuario
- Borra conexion de Firestore/SQLite
- Audit log en cada team

### 9. Hook en `confirm_contract`
- Despues de `new_status == "confirmed"`: llama `_grant_bilateral_repo_access()`
- Resultado incluido en respuesta JSON como `github_access`
- Try/catch para no romper el flujo de confirmacion si GitHub falla

### 10. Hook en `rate_user`
- Cuando `both_rated` y ambos ratings promedian < 2.0: auto-revoke via `_revoke_bilateral_repo_access()`
- Warning agregado al mensaje de respuesta
- Proteccion contra colaboraciones toxicas

### 11. Dependencies
- `pyproject.toml`: +`PyJWT>=2.0.0`, +`cryptography>=3.4`
- Ambos ya estaban instalados en venv

## Arquitectura de la integracion

```
connect_github ──→ GitHubAppClient.find_installation_for_user()
                   ├─ No instalada → retorna install_url
                   └─ Instalada → get_repos() → upsert_github_connection()
                                  └─ Si hay contratos confirmados → auto-grant

confirm_contract ──→ new_status == "confirmed"
                     └─ _grant_bilateral_repo_access()
                        ├─ Ambos conectados → add_collaborator(pull) en repos
                        └─ No ambos → skip (graceful)

rate_user ──→ both_rated && avg < 2.0
              └─ _revoke_bilateral_repo_access()
                 └─ remove_collaborator() en todos los repos

disconnect_github ──→ revoke en todos los teams
                      └─ delete_github_connection()
```
