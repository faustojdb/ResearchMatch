## 3. Analisis de competidores (completo)

4 repos clonados en `D:\cowork\competitor_analysis\`:

### 3.1 go-whatsapp-web-multidevice (3499 stars, Go)

**Arquitectura**: Go monolito con clean architecture. Usa `go-whatsapp` (Rhymen) como libreria WA nativa (no web browser como whatsapp-web.js). Soporte multi-device real. REST API (Fiber/Echo) + MCP server via `mcp-go` SDK.

**MCP Tools (24 herramientas)** organizadas por dominio:
- **Send (6)**: text (ghost mentions, reply, forwarding), contact, link, location, image (view_once, compress), sticker
- **Query (5)**: list_contacts, list_chats (pagination, search, has_media filter), get_chat_messages (time filters, media_only, is_from_me, full-text search), download_media, archive_chat
- **Group (13)**: create, join via link, leave, list participants, add/remove/promote/demote participants, get invite link, group info, set name/topic/locked/announce, list join requests, approve/reject join requests

**Patrones destacados**:
- `mcp.NewToolResultStructured()` — respuestas tipadas con fallback text (mejor que string puro)
- Tool annotations: `ReadOnlyHintAnnotation`, `DestructiveHintAnnotation`, `IdempotentHintAnnotation`
- Pagination con offset/limit en queries
- Time-range filtering (from_date/to_date) en mensajes
- Full-text search dentro de chat messages
- media_only filter para buscar solo media
- Chatwoot integration (CRM de soporte multi-canal)

**Features que nos faltan**: send contact, send link, send location, send sticker, ghost mentions, reply to specific message, forwarding, archive chat, TODAS las 13 tools de grupos, download media, time-range filtering, full-text search en chats.

### 3.2 telegram-mcp (701 stars, Python/FastMCP)

**Arquitectura**: Python FastMCP + Telethon (Telegram API client). Archivo unico `main.py` (~4000 lineas). **90+ MCP tools** — la implementacion MCP mas completa que existe.

**Categorias de tools**:
- Chat & Group (20+): get_chats, list_chats, get_chat, create_group, invite_to_group, create_channel, edit_chat_title, leave_chat, get_participants, get_admins, get_banned_users, promote_admin, demote_admin, ban_user, unban_user, get_invite_link, export/import_chat_invite, join_chat_by_link, subscribe_public_channel
- Messaging (20+): get_messages, list_messages, list_topics, send_message, reply_to_message, edit_message, delete_message, forward_message, pin/unpin_message, mark_as_read, get_message_context, get_history, get_pinned_messages, get_last_interaction, create_poll, list_inline_buttons, press_inline_button, send/remove/get_reactions
- Contacts (12): list/search/add/delete/block/unblock/import/export contacts, get_blocked_users, get_contact_ids, get_direct_chat_by_contact, get_contact_chats
- Profile (5): get_me, update_profile, delete_profile_photo, get_user_photos, get_user_status
- Search (3): search_public_chats, search_messages, resolve_username
- Stickers/Bots (3): get_sticker_sets, get_bot_info, set_bot_commands
- Privacy/Settings (8): get/set_privacy_settings, mute/unmute/archive/unarchive_chat, get_recent_actions
- Drafts (3): save/get/clear_draft
- Folders (4+): list_folders, get_folder, create/edit/delete_folder

**Patrones destacados**:
- `ToolAnnotations(title=..., openWorldHint=True, readOnlyHint=True, destructiveHint=True, idempotentHint=True)` — annotations completas en cada tool
- `@validate_id("chat_id")` decorator — validacion automatica de IDs (integers, strings, usernames)
- `log_and_format_error()` — error handling centralizado con error codes (CHAT-ERR-123)
- `ErrorCategory` enum para clasificar errores (CHAT, MSG, CONTACT, GROUP, MEDIA, PROFILE, AUTH, ADMIN, FOLDER)
- JSON logging con `python-jsonlogger` (file + console)
- Pagination universal en todas las queries
- Engagement metrics (views, forwards, reactions) en mensajes
- CI/CD: GitHub Actions (lint + format check, Docker build validation)

**Features que nos faltan**: reply_to_message, edit_message, delete_message, forward_message, pin/unpin, mark_as_read, reactions, polls, inline buttons, drafts, privacy settings, folders, contact management completo, engagement metrics, input validation decorator.

### 3.3 WhatsApp-MCP-Server (2 stars, Node.js + Python)

**Arquitectura dual**: Express.js REST API (index.js, 126 lineas) + FastMCP Python proxy (main.py, 134 lineas). El server Node maneja whatsapp-web.js directamente y expone endpoints REST. El server Python FastMCP consume esos endpoints via httpx y los expone como MCP tools.

**Tools (3)**:
- `send_message` — con include_context (retorna ultimos 5 mensajes)
- `get_recent_messages` — basico con limit
- `get_conversation` — vista normalizada me/them

**Patron interesante**: Bridge pattern Node→Python. El FastMCP proxy no toca WhatsApp directamente, solo llama al REST API de Node. Esto permite usar FastMCP (Python) como interfaz MCP mientras Node maneja la conexion WA real.

**Conclusion**: Muy basico (3 tools), pero el patron dual-language es relevante para nosotros: podriamos tener nuestro plugin Node.js como backend y Research Match (Python FastMCP) como interfaz MCP unificada.

### 3.4 automagik-omni (17 stars, Python)

**Arquitectura**: Python production-grade multi-plataforma. FastAPI REST API + CLI + multi-tenant. ~90 archivos Python en `src/`. Soporta WhatsApp (via Evolution API), Discord, y Slack (placeholder).

**Componentes clave**:
- `ChannelHandler` (ABC): interfaz abstracta con `create_instance`, `get_qr_code`, `get_status`, `restart_instance`, `logout_instance`, `delete_instance`
- `ChannelHandlerFactory`: registry pattern para channel handlers
- `MessageRouter`: routing inteligente con 3 modos (AGENT, HIVE, HYBRID) + access control ACL por telefono
- `InstanceConfig` (SQLAlchemy): modelo multi-tenant con campos para WhatsApp (Evolution), Discord, y Slack
- `EvolutionClient`: cliente HTTP para Evolution API (alternativa a whatsapp-web.js)
- Audio transcription, media decryption, mention parsing
- Streaming support (AutomagikHive) con delivery progresivo chunked
- Trace/telemetry system para message lifecycle tracking
- PostgreSQL con Alembic migrations
- Rate limiter, health checks, health monitor

**Patrones de multi-tenant**:
- Cada instancia (`InstanceConfig`) tiene su propia config de channel + agent
- Un solo server maneja N cuentas de WhatsApp simultaneamente
- Access control: whitelist/blacklist por telefono, scope por instancia
- Agent routing: puede enviar a diferentes agentes AI por instancia

**Patrones de multi-plataforma**:
- ABC `ChannelHandler` define interfaz comun
- Factory pattern para crear handlers
- `channel_type` en cada instancia ("whatsapp", "discord", "slack")
- Handlers especializados: `WhatsAppChannelHandler`, `DiscordChannelHandler`
- Message router es channel-agnostic

**Features que nos faltan**: multi-tenant (multiples cuentas WA), access control ACL, streaming progresivo, trace/telemetry, health monitoring, audio transcription, Evolution API (alternativa a whatsapp-web.js sin browser), rate limiting.

### 3.6 Recomendaciones accionables (priorizadas)

#### PRIORIDAD ALTA — Adoptar inmediatamente

1. **Tool Annotations** (de telegram-mcp y go-whatsapp)
   - Agregar `readOnlyHint`, `destructiveHint`, `idempotentHint` a cada tool
   - Impacto: Claude Desktop muestra warnings antes de acciones destructivas
   - Esfuerzo: ~1 hora, cambios en `servers/index.js`

2. **Reply to Message** (de go-whatsapp y telegram-mcp)
   - Tool `reply_to_message(chatId, messageId, text)` — fundamental para conversaciones contextuales
   - whatsapp-web.js ya soporta: `msg.reply(text)`
   - Esfuerzo: ~30 min

3. **Forward Message** (de go-whatsapp y telegram-mcp)
   - Tool `forward_message(fromChatId, messageId, toChatId)`
   - whatsapp-web.js: `msg.forward(chatId)`
   - Esfuerzo: ~30 min

4. **Mark as Read** (de telegram-mcp)
   - Tool `mark_as_read(chatId)` — util para indicar que el bot "leyo"
   - whatsapp-web.js: `chat.sendSeen()`
   - Esfuerzo: ~15 min

5. **Input Validation Decorator** (de telegram-mcp)
   - Centralizar validacion de chatId/phoneNumber con un wrapper
   - Pattern: normalize phone → @c.us, validate format, error codes
   - Esfuerzo: ~1 hora

#### PRIORIDAD MEDIA — Siguiente sprint

6. **Group Management Tools** (de go-whatsapp — 13 tools)
   - Minimo viable: create_group, add_participants, remove_participants, get_group_info
   - whatsapp-web.js soporta todo via `client.createGroup()`, `chat.addParticipants()`, etc.
   - Esfuerzo: ~4 horas

7. **Error Handling Centralizado** (de telegram-mcp)
   - `ErrorCategory` enum + `logAndFormatError()` function
   - Error codes: `CHAT-ERR-001`, `MSG-ERR-002`, etc.
   - JSON logging para debugging
   - Esfuerzo: ~2 horas

8. **Send Location/Contact/Sticker** (de go-whatsapp)

   - whatsapp-web.js: `client.sendMessage(chatId, new Location(lat, lng))`, `new Contact(..)`

9. **Reactions** (de telegram-mcp)
   - `send_reaction(chatId, messageId, emoji)` + `remove_reaction`
   - whatsapp-web.js: `msg.react(emoji)`
   - Esfuerzo: ~30 min
