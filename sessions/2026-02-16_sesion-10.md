# Sesion 10 — NEED-06: Deep Repository Analysis Tool

**Fecha:** 2026-02-16
**Version:** 2.5.1-audit-mad → 2.6.0-deep-search
**Duracion:** ~25 min

## Objetivo

Implementar `research_match_deep_search`: un tool que dado un GitHub URL (encontrado via `cold_search`), clona el repo, lo analiza con `analyze_repo.py` (1217 lineas), y retorna analisis estructurado en 4 capas. Convierte el cold_search de "busqueda superficial" a "analisis competitivo automatizado".

## Contexto

- `cold_search` ya buscaba en DB interna + GitHub en paralelo (corregido en sesion 08)
- `analyze_repo.py` existia en repo root con 5 capas de analisis, funciones importables
- Faltaba un tool MCP que uniera ambos: buscar repos → analizar uno en profundidad

## Cambios realizados

### DeepSearchInput (Pydantic model)

| Campo | Tipo | Default | Validacion |

| `include_comparison` | bool | True | Layer 3 |
| `include_scoring` | bool | False | Layer 4 (mas pesado) |

### Helpers (4 nuevos)

| Helper | Proposito |
|--------|-----------|
| `_import_analyze_repo()` | Lazy import de analyze_repo.py, retorna dict de callables |
| `_deep_search_clone()` | `git clone --depth 1 --single-branch` con timeout |
| `_deep_search_check_size()` | GitHub API `repos/{owner}/{repo}` → size en KB |
| `_deep_search_sanitize_report()` | Reemplaza paths locales con repo URL |

### MCP Tool: `research_match_deep_search`

- **Annotations:** `readOnlyHint=True`, `idempotentHint=True`, `openWorldHint=True`
- **Flujo:**
  1. Lazy import analyze_repo
  2. Check repo size via GitHub API → rechazar si > 500MB
  3. `tempfile.mkdtemp` + shallow clone
  4. Layer 1: git metadata, file tree, LOC, dependencies
  5. Layer 2: MCP framework/tool extraction (si `include_mcp_analysis`)
  6. Layer 3: gap analysis vs Research Match (si `include_comparison`)
  7. Layer 4: OT/OFC originality scoring (si `include_scoring`)
  8. Serialize → sanitize → JSON response
  9. `finally: shutil.rmtree(tmp_dir)` — cleanup siempre
- **Error handling:** Cada paso con su propio try/except
- **Stateless:** No persiste nada en DB

## Decisiones de diseno

1. **Lazy import** — no agregar dependencia hard al startup del server
2. **Solo github.com** — validacion en Pydantic regex, no constante separada
3. **`--depth 1 --single-branch`** — minimiza tamaño y tiempo del clone
4. **Sanitize paths** — nunca exponer rutas locales del server en la respuesta
5. **`include_scoring=False` default** — Layer 4 crea in-memory DB + evaluator, mas pesado
6. **Cleanup en `finally`** — shutil.rmtree incluso si crashea el analisis
7. **`openWorldHint=True`** — accede a red (GitHub API + git clone)
8. **No modifica respond_request NEXT STEPS** — deep_search es pre-team (discovery)
